# DrawTool — контекст проекта и инструкция для следующих AI

> Этот файл нужен как единый handoff-документ. Прочитай его перед любыми изменениями в проекте.  
> Проект развивается итеративно, поэтому перед редактированием обязательно сверяйся с фактическим содержимым текущей папки `src`.

## 1. Что это за проект

**DrawTool** — браузерная бесконечная доска на React + TypeScript, визуально и по взаимодействию вдохновлённая Excalidraw/Figma, но реализуемая самостоятельно.

Главная цель: сделать удобный редактор диаграмм, схем, заметок и свободного рисования с хорошим UX:

- рисование фигур на canvas;
- выделение, перемещение, изменение размера и поворот;
- текст поверх фигур;
- привязки, направляющие и выравнивание;
- история действий;
- тёмная тема по умолчанию;
- аккуратный интерфейс с компактным центральным toolbar и правой панелью свойств.

Важно: не копировать исходный код, платные ассеты или закрытые функции Excalidraw+. Допускается самостоятельная реализация похожего поведения и использование открытых иконок, например `lucide-react`.

## 2. Обязательные правила перед работой

1. **Сначала изучи актуальный `src`**, особенно:
   - модель элементов;
   - `sceneStore`;
   - `selectionStore`;
   - `historyStore`;
   - код canvas-рендера;
   - обработчики pointer events;
   - панель свойств;
   - текущие горячие клавиши.

2. **Не переписывай архитектуру без необходимости.** Делай точечные изменения и сохраняй уже работающие функции.

3. После изменения запускай:

   ```bash
   npm run typecheck
   npm run lint
   npm run build
   ```

4. Если меняются только файлы внутри `src`, пользователь предпочитает получать **полную обновлённую папку `src`**, а не набор мелких патчей.

5. Каждый жест пользователя должен быть одним действием истории:
   - начало drag/resize/rotate/draw → `historyStore.begin()`;
   - завершение → `historyStore.commit()`;
   - отмена → `historyStore.cancel()`.

6. Не создавай новый объект в `getSnapshot`/`store.get()` на каждый вызов, если он используется через `useSyncExternalStore`. Snapshot должен быть кэшированным, иначе React может вызвать бесконечный ререндер.

## 4. Текущее состояние проекта

Ниже — функциональность, добавлявшаяся в предыдущих итерациях. Реальное наличие каждой части нужно подтвердить по исходникам текущего проекта перед доработкой.

### Холст и viewport

- Бесконечный canvas.
- Панорамирование.
- Масштабирование через `Ctrl/Cmd + колесо`.
- Тёмная тема включена по умолчанию.
- Есть переключатель светлой/тёмной темы, выбор сохраняется в `localStorage`.
- Фон — небольшие точки, а не обычная клетчатая сетка.
- Оси мировых координат `(0, 0)` не должны отображаться.

### Базовые инструменты

Ожидаемые инструменты toolbar:

- выбор;
- прямоугольник;
- эллипс;
- ромб;
- линия;
- стрелка;
- текст;
- карандаш / свободное рисование;
- ластик;
- дополнительные фигуры через меню `…`.

В предыдущих итерациях также добавлялись или планировались:

- треугольник;
- шестиугольник;
- звезда;
- облако;
- фрейм;
- встроенная страница/embedded page;
- лазерная указка;
- лассо;
- дополнительные AI-пункты меню как заглушки/модальные действия.

Если какой-либо из этих инструментов сейчас отсутствует или работает частично, не восстанавливай его вслепую: сначала проверь модель данных, rendering и pointer-логику.

### Фигуры и стили

Для фигур поддерживаются или должны поддерживаться:

- цвет обводки;
- цвет заливки;
- толщина линии;
- сплошная / пунктирная / точечная линия;
- прозрачность;
- острые / скруглённые углы там, где это применимо;
- поворот;
- перемещение;
- изменение размеров;
- слои;
- дублирование;
- удаление.

### Текст

Текст является особым элементом и требует бережной поддержки:

- текст должен быть **всегда поверх фигур**;
- во время редактирования canvas не должен рисовать дубликат редактируемого текста;
- поверх canvas используется textarea/editor;
- `Enter` сохраняет текст;
- `Shift + Enter` добавляет новую строку;
- у текстового редактора есть внутренний отступ, чтобы курсор не упирался в границу;
- рамка текста должна увеличиваться по мере набора;
- при изменении размера текста должен корректно меняться визуальный размер текста, а не только пустая рамка;
- двойной клик по тексту должен открывать редактирование.

### Выделение и трансформации

- Выделенный объект имеет рамку и resize-handles.
- Над объектом есть круглая ручка поворота.
- Поворот может быть больше 360°, значение не нужно искусственно ограничивать.
- Resize должен следовать за курсором без «ускорения», дрейфа или смещения.
- `Shift` при resize сохраняет пропорции.
- `Alt` при resize меняет размер от центра.
- `Ctrl/Cmd` при resize используется для привязки.
- Поворот, resize и перемещение должны работать для фигур, текста, линий, стрелок, фреймов и свободного рисования настолько, насколько это поддерживает конкретный тип элемента.
- Selection overlay рисуется после сцены, чтобы handles оставались поверх объектов.

### История

- Есть Undo/Redo.
- Горячие клавиши:
  - `Ctrl/Cmd + Z` — undo;
  - `Ctrl/Cmd + Shift + Z` — redo;
  - `Ctrl/Cmd + Y` — redo.
- История должна быть устойчивой к быстрым drag-операциям.
- В `historyStore` snapshot должен быть кэширован. Нельзя возвращать новый объект при каждом `get()` без изменения истории.

### Правый sidebar

Правая панель — основной UI для редактирования выбранного элемента или настроек текущего инструмента.

Она должна быть справа, не перекрывать центральный toolbar и не использовать старую левую модалку.

В панели отображаются только применимые настройки:

- обводка;
- заливка;
- толщина;
- стиль линии;
- углы;
- прозрачность;
- текстовые настройки;
- действия;
- слои;
- иногда настройки конкретного инструмента.

**Пользователь попросил убрать из панели постоянные поля координат `X/Y`, ширины, высоты и угла поворота.**  
Не возвращай эти поля, пока пользователь прямо не попросит. Для поворота должен работать handle над фигурой, а не обязательный числовой блок.

### Визуальный стиль

Ориентир — тёмный, компактный интерфейс в духе Excalidraw/Figma:

- центральный floating toolbar;
- `lucide-react` для иконок;
- вместо текстовых кнопок вроде «Острые», «Штрих» использовать понятные иконки с tooltip;
- компактные группы кнопок;
- правый sidebar со свотчами, segment-кнопками и ползунками;
- тёмные поверхности, читаемый контраст, синие активные состояния;
- точечный canvas background.

## 5. Критические детали canvas-рендера

### Порядок отрисовки

Так как все элементы находятся внутри одного `<canvas>`, CSS `z-index` для отдельных фигур не работает.

Нужный порядок:

1. фон;
2. все нетекстовые элементы;
3. текстовые элементы;
4. selection overlay, handles, rotation handle;
5. временные направляющие/guide lines;
6. редактор текста в DOM поверх canvas.

Текст нужно рендерить последним среди элементов сцены, чтобы он оставался над фигурами.

### Поворот

Если у модели есть `angle`/`rotation`, renderer должен:

- сохранять context;
- переносить canvas к центру элемента;
- применять `rotate(angle)`;
- рисовать элемент относительно центра;
- восстанавливать context.

Для hit-test, resize и selection bounds всегда учитывай поворот. Если полноценный rotated hit-test ещё не реализован, используй минимально допустимое приближение, но не ломай существующую работу с обычными фигурами.

### Мировые и экранные координаты

В коде есть преобразования world/screen. Любые pointer coordinates должны проходить через существующие helper-функции.

Не смешивай напрямую:

- `clientX/clientY`;
- координаты canvas;
- экранные координаты;
- мировые координаты.

Именно такие ошибки ранее приводили к тому, что resize «убегал» от курсора.

## 6. Новая главная задача: умное перемещение и направляющие

Пользователь хочет поведение, похожее на Figma/Excalidraw при перемещении объектов.

### 6.1. Shift при перемещении

При drag выбранного объекта:

- если пользователь удерживает `Shift`, объект должен двигаться строго только по одной оси;
- ось выбирается по первому заметному направлению pointer movement:
  - если `abs(deltaX) >= abs(deltaY)`, фиксируется `Y` и меняется только `X`;
  - иначе фиксируется `X` и меняется только `Y`;
- выбранная ось должна оставаться фиксированной до завершения текущего drag;
- при отпускании Shift можно либо продолжить свободное движение, либо сохранить lock до конца жеста — выбери поведение, которое лучше согласуется с текущей реализацией, но не допускай рывков.

Пример:

```text
пользователь начал перенос;
зажал Shift;
сначала больше сдвинул вправо;
объект продолжает двигаться только по горизонтали.
```

### 6.2. Ctrl/Cmd: smart alignment guides

При перемещении объекта с `Ctrl` на Windows/Linux или `Cmd` на macOS:

- сравнивать текущий объект с другими видимыми элементами;
- проверять совпадения:
  - левые края;
  - центры по X;
  - правые края;
  - верхние края;
  - центры по Y;
  - нижние края;
- если расстояние до линии выравнивания меньше порога, например `5–8` экранных пикселей с учётом zoom:
  - подвинуть объект точно на совпадающую линию;
  - показать красную направляющую.

### 6.3. Правила направляющих

Направляющие должны быть:

- красные/розово-красные;
- тонкие;
- временные — только во время drag;
- **не на весь экран**;
- ограниченные диапазоном, который действительно связывает текущий объект и объект-цель;
- визуально доходить от одного relevant edge/center до другого, как на примерах пользователя;
- исчезать после pointer up/cancel;
- не попадать в историю и не становиться элементами сцены.

Для направляющей можно использовать отдельный transient store, например:

```ts
type AlignmentGuide =
  | {
      axis: "x";
      coordinate: number;
      fromY: number;
      toY: number;
    }
  | {
      axis: "y";
      coordinate: number;
      fromX: number;
      toX: number;
    };
```

Храни guide state отдельно от `sceneStore`.

### 6.4. Центрирование

Система должна уметь центрировать объект относительно другого объекта по X и/или Y:

- совпадение центров по горизонтали;
- совпадение центров по вертикали;
- при совпадении показывать короткую направляющую между центрами/границами, а не бесконечную линию через холст.

На первом этапе достаточно центрирования относительно других объектов. Центрирование относительно frame/страницы можно добавлять позже отдельной задачей.

### 6.5. Совместимость modifier keys

При перемещении:

| Клавиша | Поведение |
|---|---|
| `Shift` | фиксирует перемещение по X или Y |
| `Ctrl/Cmd` | включает smart alignment и snapping к объектам |
| `Alt` | не менять без отдельной задачи; возможно оставить для будущего копирования при drag |

Не ломай существующую семантику:

- `Ctrl/Cmd + колесо` — zoom;
- `Ctrl/Cmd` при resize — привязка;
- `Shift` при resize — пропорции;
- `Shift` при создании фигур — ограничение геометрии.

## 8. Ограничения и запреты

- Не возвращать `CanvasOverlay`.
- Не возвращать постоянные X/Y/Width/Height/Rotation input-поля в sidebar.
- Не рисовать мировые синие оси.
- Не использовать CSS `z-index` как решение порядка объектов внутри canvas.
- Не добавлять платные или закрытые ресурсы Excalidraw.
- Не делать большие рефакторинги «на всякий случай».
- Не ломать существующие shortcuts.
- Не добавлять направляющие как обычные `BoardElement`.
- Не создавать новый snapshot-объект на каждый вызов `useSyncExternalStore`.
- Не сохранять transient state (selection, guides, laser pointer, hover) в историю как элементы сцены.
